**阶段：**
1. **试做（第 1 周）**：5 个试做模型（加 2 个变体），走完全流程，在游戏里看效果，定画风，得到"样板模型"。
2. **量产**：按跟踪表顺序做，每完成 5–10 个跑一次自动验收和出图。
3. **收尾**：全部出图，在游戏里打一遍第 1–10 波，整体检查。

## 二、每个模型的 7 个环节

| # | 环节 | 做什么 | 工具 | 产出 / 完成标志 |
|---|---|---|---|---|
| 1 | AI 初稿 | 用 [试做5个模型.md](试做5个模型.md) 的提示词模板（风格前缀 + 单位描述）生成 3–4 个候选，挑轮廓最好的一个。也可以先用 AI 画一张正面设定图，再"图生 3D"，效果通常更稳 | Meshy / Tripo / Rodin 等 | 下载 `.glb`（带贴图），在跟踪表填"1 AI初稿 ✓" |
| 2 | 修整 | **自动部分**（`prep_model.py`，见下方命令）：缩放到规定身高、原点到脚底、居中、减面、塔放上塔座、打包贴图。**人工部分**：修贴图（去掉 AI 烘进贴图的光影，补上护甲色，修掉乱码和糊块），修造型瑕疵（手指、武器、背面） | `prep_model.py` + Blender | `art/models/<文件名>.blend` |
| 3 | 绑骨 | 人形：上传 Mixamo 自动绑骨。非人形（四足、飞行、机械）：用 Rigify 或 AI 工具自带的绑骨。塔：角色绑骨，塔座不动 | Mixamo / Blender | 一个骨架 |
| 4 | 动画 | **自动**：`process_incoming.py` 在修整后调用 `procedural_anim.py`，按类别生成程序化动作（待机 / 行走 / 攻击 / 死亡 / 施法 / 建造）。想要更好的动作时，把 Mixamo 的 FBX（Without Skin）放进 `anims/`，同名动作会替换程序化的版本 | 自动 / Mixamo | 动作齐全、命名正确 |
| 5 | 自检 | 跑自动验收，必须没有 ❌ | `check_model.py` | `art/验收报告.md` |
| 6 | 出图 | 跑出图脚本和登记脚本，必须没有裁切警告 | `render_sprites.py` + `register_sprites.py` | `h5/assets/sprites/` |
| 7 | 验收 | 按下面的标准检查，通过后在跟踪表填"7 验收 ✓" | `sprite_viewer.html` + 游戏 | 通过 / 返修 |

**自动修整命令**（第 2–4 步的机械部分一次完成）：
```bash
/Applications/Blender.app/Contents/MacOS/Blender -b -P tools/blender/prep_model.py -- --in 下载/bandit.fbx --out art/models/unit_nban.blend --category monster --height 1.7 --anims 下载/bandit_anims/
```
- 正面不朝 -Y：加 `--rotate 90`（或 180 / 270），在预览页确认"南"格面向镜头。
- 塔：加 `--pedestal`，角色会自动放到标准塔座上。
- 用 Mixamo 时，**模型和动作都下载 FBX**（模型选 With Skin，动作选 Without Skin）。格式混用会导致骨骼方向不一致、动作歪斜，脚本会提醒。

**自动道具修正：** AI 绑骨常把手持的武器、工具绑错骨骼（绑到腿上，或单独一根小骨骼）。生成动作前会自动把它们改绑到最近的手上，日志里会列出改了哪些部件。如果改错了（比如把披风当成了道具），在 `art/models/<文件名>.blend` 里手动修权重，然后**只重新出图**（`render_sprites.py --model … --key …`，再 `register_sprites.py --webp`）。注意不要再对这个模型跑 `process_incoming.py`：它会从 Tripo 原始文件重新生成 `.blend`，覆盖手动修改。

**变体的做法**（如"强壮的强盗"）：复制基础模型的 `.blend`，只改贴图颜色、加配件、调整比例，动作不动，直接走第 5–7 步。

## 三、验收标准

### A. 技术验收（自动，`check_model.py`）：必须全部没有 ❌
| 项目 | 标准 | 级别 |
|---|---|---|
| 高度 | 怪物 0.8–2.6 m，BOSS 2.5–7 m，塔 1.8–4 m（含塔座），英雄塔 1.8–4 m，守卫者 1.0–2.4 m | ❌ |
| 原点 | 模型最低点在 z = 0 ± 0.05 m | ❌ |
| 动作 | 该类别的必需动作都有，名字带关键词 | ❌ |
| 贴图 | 没有丢失的贴图 | ❌ |
| 循环 | idle / walk / build 首尾帧一致 | ⚠ |
| 面数 | 怪物 500–6000，BOSS 2000–20000，塔 / 英雄 1000–20000 三角面 | ⚠ |
| 原点居中、占地、贴图尺寸 ≤ 2048、单骨架 | 见报告 | ⚠ |

运行命令：
```bash
/Applications/Blender.app/Contents/MacOS/Blender -b -P tools/blender/check_model.py -- --batch tools/blender/batch1.csv
```

### B. 出图验收（半自动）
| 项目 | 标准 |
|---|---|
| 裁切 | 出图时没有"被画布裁切"的警告 |
| 朝向 | 在 `sprite_viewer.html` 里，"南"格面向镜头，"西"格面朝左，"东"格面朝右（8 个格子依次顺时针转） |
| 锚点 | 脚踩在十字线上；行走时不漂移、不滑步 |
| 动作 | 行走看得出迈步；攻击有明显的出手瞬间；死亡最后停在倒地姿势 |

### C. 画风验收（人工，对照试做定下的样板）
| 项目 | 标准 |
|---|---|
| 小尺寸可读 | 在游戏默认缩放下（怪物约 30–40 px 高），能一眼认出是什么，轮廓不糊成一团 |
| 护甲色 | 怪物身上的护甲色部位约占可见面积的 1/4 以上，在草地和道路背景上都醒目 |
| 风格统一 | 与样板模型的色彩饱和度、明暗对比、贴图笔触一致；不能有的写实、有的卡通 |
| 无 AI 瑕疵 | 没有多余或融合的手指、肢体，没有乱码文字和贴图上的糊块，没有左右不对称的怪异结构 |
| 光照 | 贴图里不带烘焙的高光和阴影（光照由出图脚本统一打），否则不同方向的图会"光从两边来" |
| 比例 | 在游戏里和其他单位放一起时大小合理：怪物不比塔大，BOSS 明显更大 |

**判定：** A、B 全部通过，C 没有明显问题 → 通过。否则附验收报告和截图返修，一般 1–2 轮。

## 四、AI 初稿常见问题与处理

| 问题 | 处理 |
|---|---|
| 面数几十万 | "精简"修改器降到预算；面数特别高的直接重拓扑 |
| 贴图带光影 / 高光 | 在贴图软件里压平明暗，或用"去光照"类功能重新生成贴图 |
| 不是 T-pose，四肢粘连 | 生成时加"T-pose, arms apart"；粘连部分在 Blender 里切开 |
| 手指、武器融成一团 | 武器单独建模（简单几何体即可）后绑到手骨上，比修 AI 网格快 |
| 背面没细节 / 乱 | 8 方向出图会看到背面，必须修；可以对称复制正面再改 |
| 比例不对、头太小 | 本作要求头身比约 1:4–1:5（卡通厚重感），在 Blender 里直接缩放头部 |
| 颜色和护甲色不符 | 用纯色块覆盖护甲部位，再画简单明暗 |

## 五、跟踪方式
`art/第1批任务跟踪.csv` 每个环节一列，完成填 ✓（返修填"返修 1"之类）。
- 试做的 7 项排在最前面。
- "基础模型"列有值的是变体，要等基础模型完成后再做。
- 用 Excel、Numbers 或飞书表格打开都可以。
