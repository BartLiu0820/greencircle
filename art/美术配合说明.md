# 美术配合说明（方案 A：3D 建模 → 预渲染精灵图）

## 整体流程

```
建模 + 绑骨 + 动画          出图（脚本，全自动）              登记（一条命令）         检查
art/models/<key>.blend  →  tools/blender/render_sprites.py  →  register_sprites.py  →  sprite_viewer.html / 游戏
   （美术负责）               8 方向 × 每个动作 → 精灵表         生成 sprites.js           逐个检查方向和动作
```

美术只需要交 3D 文件。相机、灯光、8 方向、帧采样、拼图、压缩、接入游戏全部由脚本完成，所有单位的角度、光照和比例保证统一。

## 一、建模规范（交付前逐条检查）

| 项目 | 要求 |
|---|---|
| 单位 | 1 Blender 单位 = 1 米 |
| 尺寸参考 | 人形怪约 1.8 m 高；塔座直径约 1.8 m（塔的角色站在塔座上）；BOSS 4–6 m；英雄塔整体约 2.5–3 m |
| 原点 | 脚底中心（塔是塔座底面中心） |
| 朝向 | 正面朝 **-Y**（Blender 前视图看到的就是正面），Z 轴朝上 |
| 骨骼 | 一个骨架；所有动作做在这个骨架上 |
| 动作命名 | 名字里包含以下关键词即可，不区分大小写，可加前缀（如 `Bandit_Walk`）：`idle` 待机、`walk` 行走、`attack` 攻击、`death` 死亡、`spell` 施法、`build` 建造 |
| 循环 | `idle` / `walk` / `build` 首尾帧一致、能无缝循环；`attack` / `spell` / `death` 播一次 |
| 死亡 | 倒地后的最终姿势停在原地附近，不要滑出太远（否则会被画布裁切，脚本会提示） |
| 面数 | 普通怪 1.5k–4k 三角面；塔、英雄、BOSS 5k–15k。出图后是 2D 图，面数只影响出图速度 |
| 贴图 | 手绘风格（接近 WC3），512–1024；Base Color 为主，可以带 Emission 做发光部位 |
| 护甲色 | 怪物要有明显的护甲色部位：物理 = 橙、魔法 = 蓝、抗性 = 绿、神圣 = 金白（详见需求清单的"可读性规则"） |
| 格式 | `.blend`（推荐）/ `.glb` / `.fbx` / `.obj` 都可以 |
| 文件名 | 按 `tools/blender/batch1.csv` 的 `model` 列命名，放进 `art/models/`。例：`unit_hfoo.blend`、`tower_箭塔.blend`、`hero_剑神.blend`、`builder.blend`。扩展名不同也能识别 |

**各类别需要的动作**（出图脚本按此采样；可以在清单的 `actions` 列单独改）：

| 类别 | 方向 | 动作（帧数） |
|---|---|---|
| 普通怪 `monster` | 8 | walk 8、death 6 |
| BOSS `boss` | 8 | walk 8、death 8、spell 8 |
| 塔 `tower` | 1 | idle 6、attack 6 |
| 英雄塔 `hero` | 8 | idle 6、attack 8、spell 8 |
| 守卫者 `builder` | 8 | idle 6、walk 8、build 6 |

**格式样例：** `art/models/test_unit.blend`（角色）和 `art/models/test_tower.blend`（塔）是脚本生成的占位模型。原点、朝向、动作命名都符合规范，可以直接打开对照。

## 二、AI 初稿的自动修整
AI 生成的模型（以及 Mixamo 的动作）先过一遍 `tools/blender/prep_model.py`。它会自动统一尺寸、原点、朝向，减面，合并动作并改名，去掉行走位移，打包贴图。人工只需要修贴图和造型。用法见 [第1批任务清单与验收标准.md](第1批任务清单与验收标准.md)。修完用 `tools/blender/check_model.py` 自动验收。

## 三、出图（任何人在本机都能跑，约 5–10 秒一个）

```bash
/Applications/Blender.app/Contents/MacOS/Blender -b -P tools/blender/render_sprites.py -- --batch tools/blender/batch1.csv --skip-done
```

```bash
python3 tools/register_sprites.py --webp
```

- 第一条：把 `art/models/` 里已经交付的模型全部出图，没交的自动跳过；`--skip-done` 表示已经出过图的不重复渲染。改了模型想重出，删掉 `h5/assets/sprites/` 里对应的图片，或去掉 `--skip-done`。
- 第二条：登记给游戏，并转成 WebP（体积约为 PNG 的 1/8）。
- 单个模型试出图：
  ```bash
  /Applications/Blender.app/Contents/MacOS/Blender -b -P tools/blender/render_sprites.py -- --model art/models/unit_hfoo.blend --key unit:hfoo --category monster
  ```
- 模型太大被裁切时，脚本会打印 `⚠ 这些动作有帧被画布裁切`。在清单的 `scale` 列填缩放（如 `0.8`）后重出即可。

**完整演示**（不需要任何美术文件，用测试模型从头跑一遍，看看效果）：
```bash
/Applications/Blender.app/Contents/MacOS/Blender -b -P tools/blender/render_sprites.py -- --model art/models/test_unit.blend --key unit:hfoo --category monster
```
```bash
python3 tools/register_sprites.py --webp
```
然后打开 `h5/sprite_viewer.html` 看 8 个方向的动画，或打开游戏看第 1 波的步兵。看完删掉 `h5/assets/sprites/unit_hfoo.*` 并重新登记，就恢复成占位图形。

## 四、检查

1. 打开 `h5/sprite_viewer.html`：每个单位 8 个方向同时播放，动作依次轮播。可以切换背景（草地 / 道路），检查轮廓清晰度和护甲色是否醒目。十字线是脚底锚点，脚应该踩在十字上。
2. 打开游戏，在对应波次看实际效果：大小比例、行走方向、死亡动画、和塔的比例。

## 五、第 1 批：76 个模型（`tools/blender/batch1.csv`）

| 组 | 数量 | 说明 |
|---|---|---|
| 守卫者 | 1 | 玩家唯一能操控的单位，优先做 |
| 英雄塔 | 4 | 剑神、枪神、邪冰、火魂 |
| 塔 | 28 | 主塔 7、原始 8、辅助 4、光环 4、另类 5；共用一个标准塔座，角色各不相同 |
| 怪物 | 40 | 第 1–10 波；同名的"强壮的 / 坚硬的…"变体与基础怪共用骨架和动画，换色 / 加装备即可 |
| BOSS | 3 | 大红牛、大豪猪×2（第 10 波） |

**建议顺序：**
1. 守卫者 + 标准塔座 + 2–3 个塔 + 第 1–3 波怪物：先跑通，确认画风。
2. 英雄塔 4 个。
3. 剩余的塔和怪物。

## 六、提速建议（可选）
- **人形怪物**：模型做好后上传 Mixamo 自动绑骨，再套用现成的行走 / 攻击 / 死亡动作。下载 FBX 后，把动作名改成规范里的关键词即可。
- **AI 生成 3D**（如 Meshy、Tripo、Rodin）：可以快速出初稿，再在 Blender 里修形、减面、重画贴图。适合怪物这类数量多、单个曝光少的单位。
- **复用**：清单里"原图参考"相同的行，可以共用一套模型和动画，只换贴图颜色。

## 七、需要你来定的事
1. **谁来做模型**：已定为 AI 生成初稿 + 人工修整，见 [第1批任务清单与验收标准.md](第1批任务清单与验收标准.md)。
2. **画风**：贴近原版 WC3 的手绘低模，还是更现代的卡通渲染？第一批的 3–5 个模型出来后，在游戏里看过再定稿比较稳。
